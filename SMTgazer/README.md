# SMTgazer
Welcome to the homepage of SMTgazer!

SMTgazer is an effective algorithm scheduling based method for SMT solving. This repository includes the implementation of SMTgazer and the experimental results.

## Datasets

The BMC, SymEx, and SyGuS datasets can be found on [Zenodo](https://doi.org/10.5281/zenodo.6521826). The SMT-COMP dataset can be found on StarExec via the [SMT-COMP website](https://smt-comp.github.io/2021/benchmarks.html).

`machfea/*_solver.json` is the file containing the candidate solvers of each dataset.

`machfea/infer_result/` is the folder containing the feature files of each dataset.

`data/` is the folder containing the running time of all solvers for each dataset.

## Getting Started

The paired SMTgazer/Sibyl checkout has a one-command installer and GPU smoke
test. Run it from the parent directory:

```bash
cd ..
./run_smtgazer.sh
```

The script creates an isolated Python 3.10 environment, installs the pinned
runtime dependencies and repository SMAC, and validates PyTorch, LightGBM,
the hybrid surrogate, and a real Sibyl embedding on the GPU. Use
`./run_smtgazer.sh --help` for full experiment options.

The SMAC surrogate defaults to LightGBM's OpenCL `device_type="gpu"` backend.
Set `SMTGAZER_LIGHTGBM_DEVICE_TYPE=cuda` for the separately compiled NVIDIA
CUDA backend. Both modes fail instead of falling back to CPU.

To train Sibyl's GNN locally on the selected CUDA GPU instead of using a
published checkpoint, run the integrated pipeline from the parent directory:

```bash
bash ./run_smtgazer.sh run --dataset SyGuS --train-sibyl --seeds 0 --overwrite
```

This builds a reusable graph cache, trains a mini-batched mixed-precision GAT,
extracts embeddings with GPU batches, and then runs SMTgazer. Each run writes
raw GPU samples to `logs/<run-id>/gpu.csv`, a phase-level utilization summary
to `logs/<run-id>/gpu-summary.json`, and GNN learning/throughput metrics beside
the trained checkpoint under `logs/<run-id>/checkpoints/`.

### Training

If you need to use SMTgazer on your own dataset named "xxx", generate the corresponding json file (`data/xxxLabels.json`) according to the format of `data/*Labels.json` and the file containing the candidate solvers like `machfea/*_solver.json`.

Generate the Sibyl GNN feature files with one checkpoint for both the training and test split:

```
python machfea/mach_run_inference.py \
  --dataset BMC \
  --labels data/BMCLabels.json \
  --query-root /path/to/BMC/queries \
  --sibyl-root ../sibyl \
  --model ../sibyl/inference/BMC/model_checkpoints/BMC_model_0.pt
```

This writes `machfea/infer_result/BMC_train_feature.json` and
`machfea/infer_result/BMC_test_feature.json`. Instances for which all solvers
time out are skipped, matching the original feature generation behavior. Use
`--device cuda:0` to run GNN inference on a CUDA device.

Change line 32 of `batchportfolio.py` to:

```
key_set = ["xxx"]
```

Uncomment the code on line 24 of `batchportfolio.py`, run:

```
python batchportfolio.py
```

The training result will be stored in the folder `output/` with the prefix `train_result`.

### Testing

Uncomment the code on line 26 of `batchportfolio.py`, run:

```
python batchportfolio.py
```

The testing result will be stored in the folder `output/` with the prefix `test_result`.

## Experimental Results

`output/` is the folder containing the scheduling sequences generated by SMTgazer on the datasets.

To calculate the PAR2 score and the number of unsolved instances for each dataset, run:

```
python calc_portfolio_result.py
```
